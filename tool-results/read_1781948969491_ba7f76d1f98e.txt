    24→    24→    24→## 1. Project Goals & Success Criteria
    25→    25→    25→
    26→    26→    26→### 1.1 Business Problem
    27→    27→    27→
    28→    28→    28→Sales leadership at a mid-sized Indian pharmaceutical company currently lacks a single, real-time view of how its field force is performing. Data lives in three disconnected systems: the CRM (which records doctor visits and call details), the ERP (which records invoices to distributors and stockists), and an expense system (which records travel & entertainment claims). Quarterly reviews take two weeks of manual Excel wrangling, and by the time the deck is ready, the data is stale.
    29→    29→    29→
    30→    30→    30→The brief asks the agent to simulate this entire ecosystem with a single fabricated dataset, then build a self-serve dashboard that any sales leader can open in a browser to answer five recurring questions: *How are we tracking against target? Are my reps covering the right doctors? Are we over-indexed on one product? Where will next quarter land? Which HCPs are slipping through the cracks?*
    31→    31→    31→
    32→    32→    32→### 1.2 Target Users
    33→    33→    33→
    34→    34→    34→The dashboard has three primary user personas. The **National Sales Head** opens the Overview page first thing every Monday morning to check last week's attainment and YoY trajectory. The **Regional Manager** drills into their zone filter to see which reps and HCPs are underperforming. The **Sales Operations analyst** uses the Field Force and HCP Targeting pages to plan next quarter's call plan and rep territory reassignment.
    35→    35→    35→
    36→    36→    36→### 1.3 Success Criteria
    37→    37→    37→
    38→    38→    38→1. The fabricated dataset covers 36 months (April 2023 → March 2026), contains ≥ 100K total rows across 7 tables, and is fully reproducible from a single Python script with `random_state = 42`.
    39→    39→    39→2. The dashboard runs locally with one command, loads any page in under 2 seconds on a 2020 MacBook Air, and renders cleanly on both 1440p desktop and 1280×800 laptop.
    40→    40→    40→3. All 5 analysis modules are accessible from the sidebar, and every module page surfaces at least 2 of the 8 mandated chart types.
    41→    41→    41→4. All 8 chart types appear at least once across the dashboard, with working hover tooltips and responsive resize.
    42→    42→    42→5. The README explains dataset generation, seeding, dev startup, and every non-obvious decision the agent made.

   107→   107→   107→### 2.3 Data Flow
   108→   108→   108→
   109→   109→   109→Server Components fetch from Prisma directly (no API needed for first render). API routes exist for two reasons: (a) to power client-side filter changes without losing server cache, and (b) to expose a clean JSON contract if the dashboard is ever embedded elsewhere.    115→   115→   115→### 3.1 Scope
   116→   116→   116→

   118→   118→   118→
   119→   119→   119→### 3.2 Naming & Format Conventions
   120→   120→   120→
   121→   121→   121→| Convention | Rule |
   122→   122→   122→|---|---|
   123→   123→   123→| Column names | snake_case, singular (`rep_id`, not `repId` or `reps_id`) |
   124→   124→   124→| Date format | ISO 8601 string `YYYY-MM-DD` in CSVs, `DateTime` in Prisma |
   125→   125→   125→| Currency | INR (Indian Rupee), stored as paise integers (1 INR = 100 paise) to avoid float drift — display layer divides by 100 |
   126→   126→   126→| IDs | String-prefixed codes: `REP-001`, `HCP-0001`, `PRD-CARD-01`, `VIS-20240105-001`, `INV-20240105-001`, `EXP-20240105-001`, `TGT-2024-Q1-REP001-PRDCARD01` |
   127→   127→   127→| NULL handling | Empty string in CSVs (Prisma maps to `null`) |
   128→   128→   128→| Booleans | `true`/`false` literal in CSVs |
   129→   129→   129→| RNG seed | `random_state = 42` everywhere (numpy, faker, pandas) |
   130→   130→   130→| File names | `reps.csv`, `hcps.csv`, `products.csv`, `visits.csv`, `sales.csv`, `expenses.csv`, `targets.csv` |
   131→   131→   131→
   132→   132→   132→### 3.3 Locale Specifics
   133→   133→   133→
   134→   134→   134→All names must come from Faker's `en_IN` locale so the dashboard reads naturally to an Indian user: first names like *Aarav*, *Priyanka*, *Vignesh*; last names like *Sharma*, *Iyer*, *Reddy*; cities limited to **Mumbai, Delhi, Bengaluru, Chennai, Kolkata, Hyderabad, Pune, Ahmedabad, Jaipur, Lucknow, Kochi, Bhopal**.    252→   252→   252→## 5. Fab Dataset — Relationships (ERD)
   253→   253→   253→
   254→   254→   254→The dataset is a classic star/snowflake schema with `reps` as the central hub. Below is the textual ERD; implement exactly these relations in Prisma.
   255→   255→   255→
   256→   256→   256→| From | To | Cardinality | Via |
   257→   257→   257→|---|---|---|---|
   258→   258→   258→| `reps` | `reps` (manager) | 1 : N | `reps.manager_id` self-reference |
   259→   259→   259→| `reps` | `visits` | 1 : N | `visits.rep_id` |
   260→   260→   260→| `reps` | `sales` | 1 : N | `sales.rep_id` |
   261→   261→   261→| `reps` | `expenses` | 1 : N | `expenses.rep_id` |
   262→   262→   262→| `reps` | `targets` | 1 : N | `targets.rep_id` |
   263→   263→   263→| `hcps` | `visits` | 1 : N | `visits.hcp_id` |
   264→   264→   264→| `hcps` | `sales` | 1 : N | `sales.hcp_id` |
   265→   265→   265→| `products` | `visits` | 1 : N (via junction string) | `visits.products_detailed` (denormalized CSV — parse in app layer) |
   266→   266→   266→| `products` | `sales` | 1 : N | `sales.product_id` |
   267→   267→   267→| `products` | `targets` | 1 : N | `targets.product_id` |
   268→   268→   268→
   269→   269→   269→The `products_detailed` field is intentionally a CSV string inside `visits` rather than a proper junction table — this keeps the schema lean for a demo project and matches how most pharma CRMs export the field. The app layer must split on `,` and join to `products` as needed.

   273→   273→   273→## 6. Fab Dataset — Generation Rules & Distributions
   274→   274→   274→
   275→   275→   275→### 6.1 Reps
   276→   276→   276→
   277→   277→   277→Generate 50 reps with the hierarchy: 1 National Head → 4 Regional Managers (one per zone) → 8 Area Managers (2 per zone) → ~37 Field Reps (4-5 per area). `hire_date` is uniformly distributed across 2020-01-01 → 2025-12-31, biased toward the middle. Apply **12% annual attrition** — each rep has a 12% chance per year of being marked `Exited` with an `exit_date` somewhere mid-year. Exited reps get replaced by a new rep with `hire_date` = old rep's `exit_date + ~14 days` to maintain coverage.
   278→   278→   278→
   279→   279→   279→### 6.2 HCPs
   280→   280→   280→
   281→   281→   281→3,000 HCPs, distributed across cities proportional to population (Mumbai ~15%, Delhi ~14%, Bengaluru ~11%, etc.). Tier distribution: **A = 20%, B = 50%, C = 30%**. Specialty correlated with therapy area focus: 30% Cardiologists, 30% Diabetologists, 20% Gastroenterologists, 20% Pulmonists. Decile recomputed each quarter based on cumulative revenue.
   282→   282→   282→
   283→   283→   283→### 6.3 Visits
   284→   284→   284→
   285→   285→   285→Each active Field Rep executes **8-12 visits per working day** (Mon-Sat). Working days = total days minus Sundays minus Indian national holidays minus state-specific holidays. Visit-to-HCP assignment is biased: Tier-A HCPs get visited ~3× per month, Tier-B ~1.5×/month, Tier-C ~0.5×/month. Visit type mix: 70% F2F, 15% Virtual, 10% Group_Detailing, 5% Conference. Outcome distribution: 60% Detailed, 25% Briefed, 10% No_Show, 5% Refused. Sample drop counts scale with HCP tier (A gets more samples).
   286→   286→   286→
   287→   287→   287→### 6.4 Sales
   288→   288→   288→
   289→   289→   289→Each Tier-A HCP generates ~2 invoices per month, Tier-B ~1/month, Tier-C ~0.3/month. Invoice value follows a **lognormal distribution** with mean driven by product MRP and HCP tier. Monthly seasonality: peaks in **March (fiscal close)** and **September (festive + half-year close)** at 1.3× baseline; dips in **May (summer slowdown)** at 0.85×. Apply an **8% YoY growth** baseline. New products follow a **6-month linear ramp** from launch date to steady-state. Discounts uniformly 2-12%.
   290→   290→   290→
   291→   291→   291→### 6.5 Expenses
   292→   292→   292→
   293→   293→   293→Each rep incurs ~5-8 expense entries per week. Travel 40%, Food 25%, Lodging 15%, Samples 10%, Other 10%. Amounts: Travel ₹200-₹2,000, Food ₹100-₹800, Lodging ₹1,500-₹4,000. Policy compliance ~95%; non-compliant flagged.
   294→   294→   294→
   295→   295→   295→### 6.6 Targets
   296→   296→   296→
   297→   297→   297→Targets are computed **bottom-up from last year's actuals × growth × stretch**: `target_qty = last_year_actual_qty × 1.15 × rep.target_stretch_pct`. For new products, base on therapeutic-area average. Targets stored at quarter granularity per rep per product.
   298→   298→   298→
   299→   299→   299→### 6.7 Reproducibility
   300→   300→   300→
   301→   301→   301→Set `numpy.random.seed(42)`, `faker.seed_instance(42)`, `random.seed(42)` at the top of the generation script. The same seed must always produce byte-identical CSVs.

   362→   362→   362→## 8. Analysis Module 1 — Sales Performance
   363→   363→   363→
   364→   364→   364→### 8.1 Metrics to Compute
   365→   365→   365→
   366→   366→   366→| Metric | Formula | Granularity |
   367→   367→   367→|---|---|---|
   368→   368→   368→| Total Sales (₹ Cr) | `SUM(net_value_inr) / 1e7` | Daily / Monthly / Quarterly |
   369→   369→   369→| Attainment % | `SUM(actual) / SUM(target) × 100` | Per rep, per zone, per product |
   370→   370→   370→| YoY Growth % | `(current_period - prior_year_period) / prior_year_period × 100` | Monthly |
   371→   371→   371→| MoM Growth % | `(current_month - prior_month) / prior_month × 100` | Monthly |
   372→   372→   372→| Sales by Zone | `SUM(net_value_inr) GROUP BY zone` | Monthly |
   373→   373→   373→| Sales by Therapy Area | `SUM(net_value_inr) GROUP BY products.therapy_area` | Monthly |
   374→   374→   374→| Top 10 Reps by Attainment | `ORDER BY attainment_pct DESC LIMIT 10` | Quarterly |
   375→   375→   375→| Bottom 10 Reps by Attainment | `ORDER BY attainment_pct ASC LIMIT 10` | Quarterly |
   376→   376→   376→| Top 10 HCPs by Revenue | `SUM(net_value_inr) GROUP BY hcp_id ORDER BY DESC LIMIT 10` | Quarterly |
   377→   377→   377→| District/State Heat | `SUM(net_value_inr) GROUP BY state` | Monthly |
   378→   378→   378→
   379→   379→   379→### 8.2 Business Logic Notes
   380→   380→   380→
   381→   381→   381→Attainment % must be computed against **same-period targets**, not annual targets. A rep who hit ₹40L of a ₹50L Q1 target shows 80% attainment, regardless of full-year target. YoY growth for new products (launched within last 12 months) should display as `N/A` rather than `infinity` — handle this in the API layer.

   406→   406→   406→## 10. Analysis Module 3 — HCP Targeting & Segmentation
   407→   407→   407→
   408→   408→   408→### 10.1 Segmentation Logic
   409→   409→   409→
   410→   410→   410→- **Tier** (A/B/C) is set at generation time based on revenue potential.
   411→   411→   411→- **Decile** (1-10) is recomputed quarterly: rank all HCPs by 90-day trailing revenue, bucket into deciles.
   412→   412→   412→- **Segment label** is derived from tier × recency: `Champion` (Tier A, visited ≤30 days), `Loyal` (Tier A, visited 30-90 days), `At Risk` (Tier A, visited >90 days), `Emerging` (Tier B, growing), `Slipping` (Tier B, declining), `Long-tail` (Tier C).
   413→   413→   413→
   414→   414→   414→### 10.2 Metrics
   415→   415→   415→
   416→   416→   416→| Metric | Formula |
   417→   417→   417→|---|---|
   418→   418→   418→| Tier-wise Coverage % | `DISTINCT hcp_id visited in tier / total in tier × 100` |
   419→   419→   419→| Decile-wise Revenue Contribution | `SUM(revenue) GROUP BY decile / total × 100` |
   420→   420→   420→| Untapped High-Value HCPs | Tier-A HCPs with 0 visits in last 90 days |
   421→   421→   421→| ROI per HCP | `SUM(revenue from HCP) / COUNT(visits to HCP)` |
   422→   422→   422→| HCP Churn (QoQ) | HCPs whose revenue dropped >50% QoQ |

   445→   445→   445→## 12. Analysis Module 5 — Forecasting
   446→   446→   446→
   447→   447→   447→### 12.1 Approach
   448→   448→   448→
   449→   449→   449→Use **statsmodels Holt-Winters Exponential Smoothing** (trend + seasonality, 12-month seasonality) on monthly revenue per region and per therapy area. Backtest on the last 3 months: train on months 1-33, predict months 34-36, compute **MAPE**. Then retrain on all 36 months and forecast the next 3 months with 80% / 95% confidence intervals.

   955→   955→   955→### 21.3 Final Notes
   956→   956→   956→
   957→   957→   957→- Treat reproducibility as a hard requirement. The same `python scripts/generate_dataset.py` run with seed 42 must produce byte-identical CSVs every time. If you find non-determinism (e.g., dict ordering, set iteration), pin it.
   958→   958→   958→- The dataset is the foundation. Spend time getting it right — every chart depends on it. A typical mistake is to generate `visits` and `sales` independently and lose the causal link (a visit should precede the sale within 14 days). The `gen_sales` function must read from the `visits` table, not generate from scratch.
   959→   959→   959→- The dashboard is a demo, not a production system. Optimize for clarity and visual polish over engineering rigor. If a 200-line Prisma query and a 50-line Prisma query produce the same chart, prefer the 50-line one.
